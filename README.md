# Projectyard: похорони репозиторий

Сайт перед запуском основного Projectyard. Человек вставляет ссылку на заброшенный репозиторий, проходит сцену похорон и получает свидетельство о смерти, которым можно поделиться. Когда наберётся 100 проектов, начнём разработку основного сайта, и все похороненные здесь проекты переедут туда.

Портфолио, которое раньше лежало в этом репозитории, сохранено в ветке `portfolio`.

**Стек:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Motion, Supabase, next/og для картинок.

## Как это устроено

1. `/` — форма. Сервер по ссылке забирает у GitHub дату создания, число коммитов, первый и последний коммит. Пользователь выбирает причину смерти и пишет эпитафию.
2. «Похоронить» запускает сцену `src/components/funeral-scene.tsx`: prep → coffin → lowering → burying → silence. До silence похороны можно отменить, в базу ещё ничего не записано. На silence могила сохраняется, и сцена переходит на страницу свидетельства.
3. `/r/<owner>/<repo>` — свидетельство и шеринг: готовый текст поста, Telegram, ВКонтакте, X, системное меню «Поделиться» с картинкой на телефоне, скачивание PNG. После сцены свидетельство появляется с раскрытием, при переходе по ссылке — сразу.
4. `/r/<owner>/<repo>/certificate.png` — картинка 1200×630. Её же соцсети прикрепляют к ссылке (og:image). `?format=story` — 1080×1920 для сторис, `?download` — отдаёт файлом.
5. В шапке счётчик «N/100 проектов», по клику попап про основной сайт.

С базой один репозиторий хоронят один раз: повторная ссылка ведёт на существующее свидетельство.

## Режим без базы

Пока не заданы `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`, база не нужна вообще, в том числе на Vercel:

- данные свидетельства лежат прямо в ссылке: `/r/<owner>/<repo>?d=…`. Такая ссылка открывает то же свидетельство и прикрепляет ту же картинку, где бы её ни открыли;
- счётчик в шапке и номер участка считаются по похоронам в этом браузере (`localStorage`), в попапе написано, что это тестовый режим;
- «уже похоронен» тоже определяется только в этом браузере.

Как только ключи появятся, сайт сам переключится на Supabase: ссылки станут короткими, счётчик — общим. Старые ссылки с `?d=` продолжат открываться.

## Supabase

1. В SQL Editor проекта основного Projectyard выполнить `supabase/migrations/0001_bury.sql`. Миграция добавляет колонки в таблицу `projects`, где сейчас только `id` и `created_at`, уникальный индекс по `slug` и политику на чтение.
2. Задать переменные окружения (см. `.env.example`):

| Переменная | Зачем |
| --- | --- |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Запись и чтение могил. Ключ используется только на сервере |
| `SITE_URL` | Адрес сайта для ссылок и og:image. Без него берётся из заголовков запроса |
| `GITHUB_TOKEN` | Необязательно. Без токена GitHub даёт 60 запросов в час, с токеном 5000 |

Строки с этого сайта помечены `source = 'bury'`, счётчик считает только их.

## Деплой на Vercel

Импортировать репозиторий, задать переменные выше, `SITE_URL` — боевой домен. Шрифты для картинок читаются из `node_modules/@fontsource` и попадают в сборку через `outputFileTracingIncludes` в `next.config.ts`.

## Варианты свидетельства

Оформление лежит в `src/certificate/variants`. Сейчас есть один вариант, `classic`. Один и тот же компонент рисует свидетельство на странице, в превью ссылки и в скачиваемом PNG.

Чтобы добавить вариант:

1. Создать `src/certificate/variants/<id>.tsx`, экспортировать объект `CertificateVariant` с `render(data, format)` для форматов `card` и `story`.
2. Дописать его в массив `variants` в `src/certificate/variants/index.ts`.
3. Выбор оформления в форме появится сам. Выбранный id сохраняется в `projects.variant`.

Пока вариант не готов, его можно смотреть на настоящих данных: `/r/<owner>/<repo>/certificate.png?variant=<id>`.

Картинки собирает Satori, поэтому в разметке варианта только flex-вёрстка и инлайн-стили, у каждого `div` с несколькими детьми явный `display: flex`, без CSS-переменных и без текста внутри `<svg>`. Шрифты берутся из `typeface` в `src/certificate/typography.ts`.

С прошлого макета остались идеи ещё для двух вариантов: «надгробие и лог» и «бумажный бланк».

## Картинки

`public/images` — картинки из основного Projectyard (репозиторий gravejects): логотип, луна с вороном на первом экране, кладбище на фоне сцены и свидетельства, пустое надгробие в сцене похорон, текстура камня. На странице они идут через `next/image`, в PNG свидетельства — как data URI (`src/certificate/server-assets.ts`).

## Промо-ролик

В `video/` — ролик для соцсетей в духе запусков Notion и Linear: 1920×1080, 30 fps, около 35 секунд. Сделан на [Remotion](https://www.remotion.dev): это React, поэтому свидетельство в ролике — тот же компонент, что на сайте, а картинки берутся из `public/images`.

```bash
cd video
npm install
npm run studio   # предпросмотр и правки в браузере
npm run render   # out/projectyard-launch.mp4
npx remotion render src/index.ts Launch out/projectyard-launch.mp4 --props='{"site":"projectyard.example"}'   # с адресом сайта в финале
```

Сцены: коммит «доделаю на выходных» → стена мёртвых репозиториев → логотип → работа с сайтом (ссылка, причина, эпитафия) → похороны → свидетельство и телефон со сторис → «Каждый проект заслуживает покоя».

| Что | Где |
| --- | --- |
| Тексты и пример репозитория | `video/src/copy.ts` |
| Длительность сцен | `SCENES` в `video/src/Launch.tsx` |
| Сами сцены | `video/src/scenes/` |

Звука в ролике нет: музыку удобнее подложить при публикации или в монтажке. Remotion бесплатен для частных лиц и команд до трёх человек.
